Project 4: Autostitching and Photo Mosaics

Part A: Image Warping and Mosaicing

In Part A I stitch photos taken from one spot into panoramas using correspondences that I click by hand. I solve for the homography between each pair of overlapping photos, warp the photos with inverse warping, and blend them into a single mosaic. The same warping code also rectifies photos of flat objects so that they look like they were taken straight on.

A.1 Shoot the Pictures

I took three sets of photos for mosaics: Hilgard Hall, a street of houses, and a wooded path with a footbridge. For each set I stood in one place and rotated the camera between shots, with at least half of each photo overlapping the next, so that the photos in a set are related by a projective transformation. For rectification I took two photos of flat objects at an angle, a door and a sign, which are shown in A.3. All photos are 1000 by 750 pixels.

A.2 Recover Homographies

A homography H is a 3 by 3 matrix that maps a point (x, y) in one image to a point (x′, y′) in another through homogeneous coordinates, so that [w x′, w y′, w]T = H [x, y, 1]T and the result is divided by w. H is only defined up to scale, so I fix h33 = 1, which leaves 8 unknowns. Writing out the division gives x′ = (h11x + h12y + h13) / (h31x + h32y + 1) and the same for y′ with the second row of H, and multiplying both sides by the denominator makes each equation linear in the unknowns, so every correspondence adds two rows to a linear system Ah = b:

For each correspondence (x, y) -> (x', y'): h11 x + h12 y + h13 - h31 x x' - h32 y x' = x' h21 x + h22 y + h23 - h31 x y' - h32 y y' = y' Stacking the two rows for every point i = 1, ..., n: ⎡ x1 y1 1 0 0 0 -x1 x1' -y1 x1' ⎤ ⎡ h11 ⎤ ⎡ x1' ⎤ ⎢ 0 0 0 x1 y1 1 -x1 y1' -y1 y1' ⎥ ⎢ h12 ⎥ ⎢ y1' ⎥ ⎢ : ⎥ ⎢ : ⎥ = ⎢ : ⎥ ⎢ xn yn 1 0 0 0 -xn xn' -yn xn' ⎥ ⎢ ⎥ ⎢ xn' ⎥ ⎣ 0 0 0 xn yn 1 -xn yn' -yn yn' ⎦ ⎣ h32 ⎦ ⎣ yn' ⎦ A is 2n x 8, h = [h11 h12 h13 h21 h22 h23 h31 h32]^T, b is 2n x 1

Four points give exactly 8 equations, but clicked points are off by a pixel or two, so I click 8 points for every pair and solve the overdetermined system with least squares using np.linalg.lstsq, which spreads the click error over all of the points. I then append h33 = 1 and reshape h into H.

A.3 Warp the Images

To warp an image by H, I first map its four corners through H to find the bounding box of the output. For every pixel in that box I apply H−1 to find where it comes from in the source image, which is inverse warping: every output pixel gets exactly one value, so there are none of the holes that forward warping leaves. The alpha mask marks the output pixels whose source location falls inside the source image, and the pixels outside it are set to 0. The whole grid is computed at once with np.meshgrid and one matrix multiplication, without any Python loops over pixels.

The two warp functions differ only in how they sample the source at a non integer location. Nearest neighbor rounds the location to the closest pixel and copies its value, while bilinear takes the four surrounding pixels and averages them with weights based on how close the location is to each one.

Rectification

To rectify a photo, I click the four corners of a flat rectangular object and compute H from those corners to the corners of an axis aligned rectangle, 360 by 800 for the door and 200 by 700 for the sign. I then warp the photo with that H and crop the result to the rectangle. The corners of the photo far from the object can map very far away, or past the horizon line where w becomes negative, so for rectification I warp into a fixed box 200 pixels larger than the rectangle on every side instead of the full bounding box.

Nearest Neighbor vs. Bilinear

The zoomed crops below are enlarged without smoothing so the individual pixels are visible. Nearest neighbor leaves jagged stair steps along the door's moldings and the edges of the letters, because neighboring output pixels round to the same source pixel or skip over one, while bilinear gives smooth edges at the cost of a slight softening. Bilinear takes about twice as long, since it reads four pixels and computes their weights for every output pixel instead of reading one, but both are fast because they are vectorized, so I use bilinear for the mosaics.

A.4 Blend the Images into a Mosaic

For each set I use the middle photo as the reference, so the outer photos are warped toward it and the distortion is split between the two sides. I compute the homography between each neighboring pair from 8 clicked points, use H12 directly for the left photo, and use the inverse of H23 for the right photo, since that maps it into the middle photo's frame. Mapping the corners of all three photos through their homographies gives the bounding box of the mosaic, and each photo is warped with bilinear interpolation onto that one shared canvas.

To blend, each photo gets a weight at every canvas pixel equal to the distance to the nearest edge of its alpha mask, computed with distance_transform_edt, so a photo counts the most at its center and fades to zero at its border. Feathering divides the weighted sum of the photos by the sum of the weights, which removes the hard seam but softens fine detail in the overlap wherever the photos are slightly misaligned. I use two band blending instead: I split each warped photo into a low frequency band, a Gaussian blur with σ = 2 that is divided by the blurred mask so the black outside the photo does not leak in, and a high frequency band, which is the photo minus its low band. The low bands are averaged with the distance weights, so the colors change gradually across the overlap, and at each pixel the high band is taken entirely from the photo with the largest weight, which keeps edges and texture sharp instead of averaging two slightly offset copies.
